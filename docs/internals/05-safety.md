# 05. 安全機構・フェイルセーフ仕様

## 基本原則

ファン制御ソフトウェアの不具合や停止は、サーバーの熱暴走やハードウェア損傷に直結する。
そのため、`pmgfan` では以下の原則を最重要設計指針としている：

1. **独自制御は「完全な情報が揃っている時」に限り許される**:
   温度や回転数が読めない、あるいは IPMI 通信が怪しい状況では、直ちに独自判断を放棄する。
2. **異常時はハードウェア本来の制御（iRMC S5 自動制御）へ戻す**:
   サーバーマザーボードの iRMC S5 は独立したハードウェア制御ロジックを備えており、オーバーライドを解除すれば安全に冷却を行える。
3. **プロセスハング・OS クラッシュまで想定する**:
   万が一 `pmgfand` プロセス自体がデッドロックやクラッシュを起こしても、systemd watchdog やタイムアウトによって放置されない設計とする。

## セーフティ状態機械 (`crates/daemon/src/safety.rs`)

デーモン内部の安全管理モジュールは、以下の 3 つの状態で遷移する。

```text
               ┌───────────────┐
               │    Normal     │◄───────────────────┐
               └───────┬───────┘                    │
                       │                            │
         異常検知       │ IPMI エラー連続 /           │ 異常解消 &
         (センサー喪失)  │ 基準ファン喪失             │ 条件クリア
                       ▼                            │
               ┌───────────────┐                    │
               │   Degraded    │────────────────────┤
               └───────┬───────┘                    │
                       │                            │
                       │ 緊急温度到達                │
                       ▼                            │
               ┌───────────────┐                    │
               │   Failsafe    │────────────────────┘
               └───────────────┘
```

### 1. `Normal`（正常状態）
- すべてのセンサー（温度・RPM）が制限時間内に正常更新されている。
- IPMI コマンドの送受信が成功している。
- ユーザー指定のモード（Curve / Fixed PWM / Target RPM）で制御を実行。

### 2. `Degraded`（機能縮小・安全退避）
- **トリガー条件**:
  - IPMI 通信の連続失敗が `ipmi_failure_limit`（既定: 3回）に達した。
  - Target RPM 制御中に基準ファン（`reference_fan`）が読み取れなくなった。
  - いずれかの動作ファンで 0 RPM（停止）が検知された。
- **動作**:
  - `fail_action = "irmc-auto"`（既定）の場合、即座に OEM override を解除して iRMC 自動制御へ戻す。
  - 状態ログに警告を出力。

### 3. `Failsafe`（緊急事態・最大冷却）
- **トリガー条件**:
  - CPU パッケージ温度が `cpu_emergency`（既定: 90°C）に到達した。
  - PCH 温度が `pch_emergency`（既定: 95°C）に到達した。
- **動作**:
  - 現在の動作モードに関わらず、即座に **100% PWM（全開回転）** を強制。
  - 温度が安全域（緊急閾値 - ヒステリシス）まで下がるまで 100% 冷却を維持。

## 異常検知のタイムアウトと閾値

| 項目 | 規定値 | 動作 |
|---|---|---|
| `sensor_stale_seconds` | 10 秒 | 温度データが 10 秒以上更新されなければセンサー喪失と判断し `fail_action` 発動 |
| `ipmi_failure_limit` | 3 回 | 読み書きコマンドが 3 回連続で失敗した場合に `Degraded` へ移行 |
| `cpu_emergency` | 90 °C | 到達で即座に `Failsafe`（PWM 100%）へ移行 |
| `pch_emergency` | 95 °C | 到達で即座に `Failsafe`（PWM 100%）へ移行 |

## systemd Watchdog 連携

`pmgfand.service` には systemd watchdog（`WatchdogSec=10s`）が設定されている。

1. デーモンの制御ループが健全に回っている限り、定期的に `sd_notify("WATCHDOG=1")` を systemd へ送信する。
2. もしメインループがデッドロックやハングアップを起こし、10秒以内に notify が届かなかった場合、systemd がプロセスを強制終了（SIGABRT / SIGKILL）して自動再起動する。
3. デーモンの終了ハンドラ（および再起動時の初期化処理）により、残存した OEM 強制はクリアされ、サーバーは直ちに安全な状態へ復帰する。

---

## プロセス終了時のクリーンアップ

デーモンが `SIGTERM`, `SIGINT`, `SIGHUP` を受信して終了する際、非同期ランタイムはシャットダウン処理を実行し、iRMC に対して **強制解除コマンド（`clear_override`）を発行してから終了** する。
これにより、デーモンを停止した後に手動でファン設定を戻す手間が不要となっている。
