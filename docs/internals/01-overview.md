# 01. 概要・目的・設計方針

## 目的

Fujitsu **PRIMERGY TX1320 M4**（iRMC S5 搭載）の冷却ファンを、iRMC 標準制御とは独立して柔軟かつ安全に制御できるようにする。

- **静音化**: アイドル時や夜間帯は低回転で静かに運用したい。
- **高負荷冷却**: 逆に高負荷時は iRMC 標準より積極的に冷却し、CPU や PCH、NVMe の熱ダレを防ぎたい。
- **常時可視化**: 温度や回転数を TUI や CLI で常時モニタリングしたい。
- **絶対安全の保証**: 制御系やセンサーが壊れたときは**必ず iRMC 本来の制御へ安全に戻る**ことをハードウェア・ソフトウェアの両面で保証する。

---

## 背景

既存の Python 実装 `fujitsu-1320-m4-fancontrol` により、TX1320 M4 / iRMC S5 に対して Fujitsu OEM IPMI コマンドによる PWM 強制・解除が可能であることが実証されている（検証環境: iRMC S5 3.31P / SDR 3.40）。

本プロジェクト `pmgfan` は、このプロトコル部分を Rust に移植し、堅牢な安全機構、ファンカーブ評価、目標回転数へのフィードバック制御（Target RPM PI 制御）、リアルタイム TUI、そしてカーネル ioctl による native バックエンドを備えたプロダクショングレードのツール群として再設計・実装した。

---

## 設計方針

### 1. 権限分離

iRMC および `/dev/ipmi0` を直接操作するのは常駐デーモン `pmgfand` のみ。
TUI/CLI `pmgfanctl` は Unix ドメインソケット経由で指示を出すだけであり、root 権限も `/dev/ipmi0` への直接アクセス権も持たない。これにより、一般ユーザーが安全に監視・操作を行える。

### 2. フェイルセーフ最優先

独自制御は「安全が完全に担保されている場合のみ」適用する。
判断に必要な情報（温度・RPM・IPMI 応答）が途絶した瞬間に OEM override を解除し、iRMC 標準制御へ即座に戻す。詳細は [05-safety.md](05-safety.md)。

### 3. Auto = iRMC 復帰

モード名 `Auto` は pmgfan 独自の自動制御**ではなく**、OEM 強制設定を解除して **iRMC 本来の制御へ戻す** ことを意味する。

### 4. スコープ分離による静音化

実機調査の結果、電源ユニット（PSU）ファンは独自の自律フロアを持っており、全体 PWM 強制（`0xff`）を行うと逆に爆音化することが判明した。
そのため、シャーシファン（FAN CPU / FAN1 SYS）のみを制御対象とし、PSU ファンは iRMC 自動制御に残す `pwm_scope = "chassis"` を標準とする。詳細は [03-ipmi.md](03-ipmi.md)。

### 5. TUI を閉じても制御は継続

制御状態とループを保持するのは常駐デーモン `pmgfand`。TUI はあくまでビューア/エディタであり、閉じてもバックグラウンドでデーモンが制御を継続する。

## システム名称と主要パス

| 名前 | 種別 | 説明 |
|---|---|---|
| `pmgfan` | プロジェクト名 | リポジトリ名、およびソケットアクセス許可用のシステムグループ名 |
| `pmgfand` | デーモン | systemd 管理の常駐プロセス（root 実行） |
| `pmgfanctl` | クライアント | CLI + TUI バイナリ（非 root 実行） |

主要ファイルパス:

| パス | 用途 |
|---|---|
| `/etc/pmgfand/config.toml` | 設定ファイル（所有権: `root:pmgfan 0640`） |
| `/run/pmgfand/control.sock` | Unix ドメインソケット（所有権: `root:pmgfan 0750`） |
| `/var/lib/pmgfand/calibration.toml` | 自動キャリブレーション結果データ |
| `/usr/lib/systemd/system/pmgfand.service` | systemd サービスユニット定義 |
